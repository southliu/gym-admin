## 论文逻辑闭环 — 实现计划

根据论文描述，当前项目缺失3个关键功能导致逻辑无法闭环。以下是具体修改方案：

---

### 任务一：用户注册功能（论文 3.1/3.3/4.3.1 节要求）

**问题**：论文描述会员可以"注册账号"，但后端无公开注册接口，前端无注册页面。

**后端修改**（`south-admin-nest/src/system/`）：
1. **`dto/user.dto.ts`** — 新增 `RegisterDto`（username、password、name可选、phone可选），不含 roleIds/status
2. **`user.service.ts`** — 新增 `register()` 方法：校验用户名唯一 → bcrypt 加密 → 自动分配 `member` 角色（通过 `roleRepository.findOne({ where: { name: 'member' } })`）→ 保存用户 → 返回 JWT token + 用户信息 + 权限（复用 login 逻辑完成登录）
3. **`user.controller.ts`** — 新增 `@Public() @Post('register')` 端点

**前端修改**（`south-admin-react/src/`）：
4. **`pages/register/index.tsx`** — 新建注册页面，样式复用 Login 页面，表单字段：用户名、密码、确认密码、姓名（可选）、手机号（可选）。注册成功后自动登录跳转
5. **`servers/login/index.ts`** — 新增 `register(data)` API 调用 `POST /system/user/register`
6. **`pages/login/index.tsx`** — 在"忘记密码"旁边增加"注册账号"链接，点击跳转 `/register`

---

### 任务二：Dashboard 数据统计（论文 4.2/4.5 节的"数据分析统计模块"）

**问题**：Dashboard 后端返回全零硬编码数据，前端显示无关领域的假数据（充值金额、游戏数量等），论文描述有课程预约数据、会员活跃度等统计。

**后端修改**（`south-admin-nest/src/dashboard/`）：
1. **`dashboard.module.ts`** — 导入 `TypeOrmModule.forFeature([User, Course, CourseSession, Booking, Coach])` 注入所需 Repository
2. **`dashboard.service.ts`** — 实现真实统计逻辑：
   - `totalMembers`：统计 role 包含 member 的用户数
   - `totalCourses`：未删除的课程总数
   - `totalSessions`：未删除的课次总数
   - `totalBookings`：活跃预约数（status=1）
   - `totalCoaches`：未删除的教练数
   - `topCourses`：热门课程 Top 5（按预约数排序，复用已有 `CourseService.stats()` 的查询逻辑）
3. **`dashboard.controller.ts`** — 注入 DashboardService，`list()` 返回真实统计数据

**前端修改**（`south-admin-react/src/pages/dashboard/`）：
4. **`index.tsx`** — 调用 API 后将数据存储到 state，移除无用的 BaseSearch 日期筛选器
5. **`components/Block.tsx`** — 改为接收 props，显示健身房相关指标：会员总数、课程总数、预约总数、教练总数，数据从 API 获取
6. **`components/Bar.tsx`** — 改为显示热门课程预约柱状图（topCourses 数据）
7. **`components/Line.tsx`** — 改为显示课次预约趋势折线图（按 sessionDate 分组统计近期每日预约数）
8. **`servers/dashboard/index.ts`** — 修正 API 路径为 `/dashboard/list` 匹配后端路由

---

### 任务三：教练排班时间冲突检测（论文 4.3.3 节要求）

**问题**：当前 `create()` 只检查同教练+同星期是否已有模板（相同天只能排一条），未检测时间重叠。论文描述"自动检测排班冲突"。

**后端修改**（`south-admin-nest/src/gym/coach-schedule-template/`）：
1. **`coach-schedule-template.service.ts` 的 `create()` 方法** — 将冲突检测从"同天查重"改为"时间重叠检测"：
   - 查询同教练+同星期的所有未删除模板
   - 检查新模板的 `[startTime, endTime)` 是否与已有模板的时间段有交集
   - 有交集则抛出 `BadRequestException('该时段与已有排班存在冲突')`
2. **`update()` 方法** — 同样增加时间重叠检测（排除自身记录）
3. **`batchGenerate()` 方法** — 保持现有逻辑不变（按模板展开+跳过请假日期，论文代码示例一致）
